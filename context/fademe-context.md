# FadeMe.ai — Project Context

## What it is
FadeMe.ai is an AI-powered prediction market bet analyzer. Users upload a screenshot of a prediction market bet and get an AI-generated grade (S–F), edge score, recommendation (BUY / HOLD / FADE), bull/bear case, key risks, and a true probability estimate vs. the market's implied probability.

**Live URL**: https://www.fademe.ai  
**Vercel project**: prediction-analyzer  
**Local repo**: `~/Desktop/GIT REPO'S/prediction-analyzer`

## Key Features (all shipped)

### Core product
- Screenshot → AI analysis (grade S-F, edge score, BUY/HOLD/FADE, bull/bear, key risks)
- Free tier: 1 analysis per non-subscriber (atomic claim via `free_analysis_claims`)
- Subscription gating with sticky conversion banner after free analysis used

### Daily picks (`/picks`)
- Subscribers + free users (limited view) see today's AI-curated picks
- Picks generated by cron at 9am ET — fetches live Kalshi/Polymarket/PredictIt markets + Tavily news, calls Claude, saves to `daily_picks`, emails subscribers
- Free users can paper trade picks (virtual money); subscribers see full analysis + edge scores
- Admin can manually mark picks Won/Lost/Void via inline controls

### Paper trading (`/portfolio`)
- Users place virtual trades on daily picks
- Results auto-resolve via Kalshi/Polymarket settlement APIs (cron at 7am ET)

### Track record (`/record`) — just built
- **Public page, no auth required** — shareable URL showing AI pick performance
- Shows W-L-V record, win rate, "tracking since" date
- Every pick has a "Verify" link to the original market on Kalshi/PredictIt
- Only shows picks with `market_id` — so every result is independently verifiable
- Transparency callout: results resolved via market settlement APIs, not manually set
- Results are auto-resolved by a new cron (noon ET daily) — admin marks are NOT overwritten

### Blog
- Auto-generated daily at 10am ET from that day's picks via Claude → publishes to Sanity
- Live at `/blog`; Sanity Studio at `/studio`

### SEO
- Sitemap, robots.txt, JSON-LD structured data
- `/record` page now included in sitemap

## Platform Detection Notes
- Visual fingerprint prompt covers 7 platforms: Kalshi binary, Kalshi sports (multipliers 2.01x, % circles, vol, "Spread and Total" label), Polymarket, PredictIt, etc.
- Polymarket outcome resolution uses 0.95/0.05 thresholds (not 0.99/0.01) — markets settle at 0.95–0.98

## Important Architectural Constraints

- **Polymarket market IDs**: stored as the Gamma API numeric `m.id`, NOT the public slug. So `polymarket.com/event/[id]` will 404. The verify link on `/record` falls back to `polymarket.com/markets`. Kalshi tickers map directly to `kalshi.com/markets/[ticker]`.
- **Win rate logic**: BUY YES wins if market resolves yes. FADE YES wins if market resolves no. BUY NO wins if market resolves no. FADE NO wins if market resolves yes. HOLD picks never auto-resolve and don't count in the record.
- **Public vs subscriber record**: `/api/record` (public) shows only picks with `market_id`. `/api/picks` subscriber record shows all resolved picks including manually-marked ones. Intentional — public page prioritizes verifiability.
- **Admin user ID**: set via `ADMIN_USER_ID` env var (Clerk user ID). Admin sees inline mark Won/Lost/Void controls on `/picks`.
- **Free analysis claim**: uses `INSERT ... ON CONFLICT DO NOTHING` pattern for atomic race-condition safety.
